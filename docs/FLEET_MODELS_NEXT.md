# Next models on the fleet: device path for MiMo-V2.6-Flash and DeepSeek V4.1 Flash

Written 2026-11-21 on branch `fable/engine-mimo-deepseek-2026-11-21` after the CPU groundwork (facts:
`MODEL_MIMO2.md`, `MODEL_DEEPSEEK4.md`; parity numbers: `WORK_LOG.md`, 2026-11-21 entry). This is the list of what the
CubeCL device path still needs, the byte table a placement generator can read, and what crosses a pipeline stage
boundary per token. Plan context: `~/agentnotes/lemonade-burn-fleet-span-plan-2026-11-21.md` (S1 kernels, S2 model
crate, S3 pipeline).

## 1. Device kernels: what exists, what is new

Existing CubeCL kernels (lb-q4-gpu, used by lb-lfm2 and lb-qwen35), CUDA and Vulkan (wgpu) from the same source:

| Kernel family | Where | Types |
|---|---|---|
| dense matvec / routed (MoE) matvec, decode | `lib.rs`, `kquant.rs` | Q4_0, Q8_0, Q6_K, Q5_K (routed variants for Q4_0, Q5_K, Q6_K, Q8_0) |
| prefill GEMM | `gemm.rs`, `qgemm.rs`, `qprefill.rs` | Q4_0 (+ int8 dot paths) |
| transcode at load | `transcode.rs` | IQ4_XS -> Q4_0 (lossless re-blocking) |
| LittleBit factorised layers | `littlebit.rs` | sub-1-bit |
| RMS norm, add+norm, SiLU-mul, copy, argmax | `qwen_ops.rs` | f32 |
| softmax router top-k + combine (shared expert gate) | `qwen_ops.rs` `qw_route_kernel`, `qw_moe_combine_kernel` | f32, softmax only |
| attention decode (GQA, head 256, full causal, no sinks), tiled prefill attention | `qwen_ops.rs` `qw_attn_*` | f32 / f16 KV |

### MiMo-V2.6-Flash (Q2_K file) needs

| New | Why | Notes |
|---|---|---|
| **Q2_K** dense + routed matvec, and a prefill GEMM | 94 expert tensors (gate/up), 61.7 GiB | repack like Q5_K (`kquant.rs`): widen 2-bit quants to bytes, fold `d*sc` and `dmin*m` per 16-value group at load; CPU oracle `lb_gguf::types::dequant_q2_k_block` (bit-exact vs ggml) |
| **MXFP4** dense + routed matvec, prefill GEMM | 47 down-expert tensors, 49.9 GiB | simplest of all: 16-entry level table x power-of-two scale; scale can be applied as an exponent add (`ldexp`) or folded to f32 at repack; oracle `dequant_mxfp4_block` / `dot_mxfp4` |
| sigmoid router with selection bias, normalised weights, no shared expert | every MoE layer | `qw_route_kernel` is softmax; lb-lfm2 has a sigmoid+bias router on CPU to copy the semantics from |
| attention: Q/K head 192, V head 128, GQA 64/4 (full) and 64/8 (sliding), **sliding window 128**, **per-head sinks**, partial NEOX rope (64 of 192), two rope bases | all 48 layers | new decode kernel (the qwen one assumes K=V width 256, no window, no sink); KV for sliding layers can be a 128-slot ring |
| value_scale (x0.707 after `attn_output`) | all layers | fold into the `attn_output` scale at load (exact in f32 only if done per output; or a scalar multiply) |
| fused QKV split with unequal widths | all layers | index arithmetic only |

Per-card note: Q8_0 attention/embedding/head kernels exist, so a first device version can run attention + head on the
card with experts on CPU (lb-lfm2's spill path), then move experts when Q2_K/MXFP4 kernels exist.

### DeepSeek V4.1 Flash (GSQ-RCO file) needs

| New | Why | Notes |
|---|---|---|
| **IQ1_M**, **IQ2_XXS**, **IQ2_XS** routed matvec (+ GEMM) | 120 expert tensors, 61.5 GiB | lattice decoders (grids in `lb_gguf::iq_grids`, CPU decoders bit-exact); grids must sit in device memory or constant tables (IQ2_XS grid 512 x u64, IQ1 2048 x u64) |
| **BF16** matvec | router, compressor, indexer | trivial |
| **IQ4_NL** row gather | Engram table (110.6 GB, stays on host) | only 2 x 24 rows of 256 per token: gather on the host (mmap) and upload 2 x 6144 floats, or keep the table on NVMe/Optane; no device kernel needed |
| Q5_K, Q8_0 | q_b, wo_a/b, shared expert, embd/head, q_a, kv | exist |
| hyper-connection kernels: 20480-wide RMS + 24-row matvec, sigmoid mixes, 4x4 Sinkhorn (20 iters), pre-collapse, post-mix | every sublayer (80 per token) | tiny but latency-bound: fuse into one kernel per sublayer |
| MQA attention, one 512-wide K=V head, sinks, NORM rope on channels 448..511 with yarn, de-rope of the output | every layer | new decode kernel; K=V halves the KV bytes |
| KV compressor (ratio 1 / ratio 2 softmax gate) + cross-layer row sharing | layers 2, 8, 14, 20 write; others read | rows are 512 (+128 indexer key) values per 1 or 2 tokens |
| lightning indexer + top-k + candidate blocks | needed past 512 compressed rows (512 tokens at ratio 1) | not needed for a first short-context version (CPU reference refuses > 128 tokens) |
| grouped output LoRA (8 groups of 4096 -> 1024) | every layer | batched matvec over groups |
| sqrt(softplus) router, x1.5 scale, SwiGLU clamp 10, shared expert | every layer | |

## 2. Layer memory tables (bytes, from the GGUF tensor table)

Generated by `cargo run --release -p lb-gguf --example gguf_facts -- <shard 1> --layers`; full tables in
`docs/models-facts/mimo2-layer-bytes.txt` and `deepseek41-layer-bytes.txt` (one row per layer: expert bytes, non-expert
bytes, total). A placement generator should read those files (or run the tool) rather than these summaries.

### MiMo-V2.6-Flash Q2_K (total 126,359,970,560 bytes)

| Layers | Experts | Non-expert (attention, norms, router) | Total per layer |
|---|---|---|---|
| 0 (dense FFN) | 0 | 308,641,792 | 308,641,792 |
| 1-47, sliding (kv 8) | 2,550,136,832 | 104,498,432 | 2,654,635,264 |
| 5, 11, 17, 23, 29, 35, 41, 47, full (kv 4) | 2,550,136,832 | 98,927,616 | 2,649,064,448 |
| outside layers (token_embd + output Q8_0, output_norm) | | 1,328,037,888 | |

One expert (gate + up + down) = 2,550,136,832 / 256 = 9,961,472 bytes; a token touches 8 per MoE layer (79.7 MB) plus the
non-expert ~104 MB per layer. Sum over layers: 125.03 GB, so with 1.33 GB of embedding/head the four-node budget in the
plan (about 156-160 GB of VRAM) holds the whole Q2_K model.

KV cache (f16): full layers 4 x (192 + 128) = 1,280 values = 2,560 bytes per token per layer (9 layers); sliding
layers 8 x 320 = 2,560 values = 5,120 bytes per token per layer, capped at 128 tokens (39 layers: 25.6 MB total, fixed).
At 32k context: 9 x 2,560 x 32,768 = 755 MB for the full layers.

### DeepSeek V4.1 Flash GSQ-RCO (total 182,713,009,888 bytes)

| Layers | Experts | Non-expert | Notes |
|---|---|---|---|
| 0-39 | 1,486,356,480 - 1,964,113,920 (quant mix varies by layer: IQ1_M / IQ2_XXS / IQ2_XS per tensor) | 120,767,448 typical | sum experts 60.86 GB, non-expert 5.0 GB |
| 1, 14 (Engram) | | +108 MB (`engram_kv` Q5_K) | 228,983,768 / 250,047,... see file |
| 2, 8, 14, 20 (KV sources), 24, 28, 32, 36 (index sources) | | +11-21 MB (BF16 compressor / indexer) | |
| outside layers | | 111,505,442,080 | Engram table 110,595,290,400 (host) + token_embd/output Q5_K 2 x 455 MB |

Without the Engram table the model is 72.1 GB: it fits in the fleet's VRAM with room to spare; the Engram table stays on
a host (mmap of the GGUF, page cache or NVMe), 24 rows x 144 bytes x 2 layers = 6.9 KB read per token.

## 3. What crosses a stage boundary per token

| Model | Residual state | Extra state that must follow it | Bytes per token (f16) |
|---|---|---|---|
| MiMo | hidden 4096 | nothing (KV stays with its layers) | 8,192 (16,384 in f32) |
| DeepSeek V4.1 | 4 hyper-connection streams x 5120 = 20,480 values, plus the lagged FFN pre-mix weights of the last layer before the boundary (4 floats) | if the boundary falls between a KV-source layer and its readers (2 -> 3..7, 8 -> 9..13, 14 -> 15..19, 20 -> 21..39), the new compressed row (512 values, +128 indexer key past 512 rows) every 1 or 2 tokens; past 512 tokens also the top-k index list (512 ints) of the latest index-source layer; the token id (Engram hashing needs the last 4 ids) | 40,968 (+1,024-1,280 when a compressed row crosses) |

Placement rule for DeepSeek that keeps the boundary at 40 KB: cut only just before a KV-source layer (2, 8, 14, 20), so
every reader shares a stage with its source; layers 20-39 (19 readers of layer 20) then form one group of ~36 GB
(experts) that must itself be cut once, costing the compressed-row hand-off (1 KB per token).

Prefill chunk of 512 tokens: MiMo 4 MB, DeepSeek 20 MB per hop (f16).

## 4. Exact next steps for the device path

1. `lb-q4-gpu`: Q2_K and MXFP4 repack + dense/routed decode matvec (CUDA + Vulkan); gate = bit-parity with
   `lb_gguf` dequant (within f32 summation order) on every card type, the S1 gate of the plan. Then a prefill GEMM for both.
2. `lb-mimo2` device layer: attention kernel for 192/128 heads with window 128 + sinks + two rope bases; sigmoid router
   with bias; parity gate per layer against `lb-mimo2`'s CPU taps (which match llama.cpp, see WORK_LOG).
3. Expert spill for the t440/c4 single-box test (lb-lfm2 cache tiers) before the pipeline (S3).
4. DeepSeek: finish the CPU parity of `lb-deepseek4` first (WORK_LOG), then IQ1_M/IQ2_XXS/IQ2_XS routed kernels
   (largest bytes), then the hyper-connection fused kernel and the MQA/compressor attention; indexer last.
